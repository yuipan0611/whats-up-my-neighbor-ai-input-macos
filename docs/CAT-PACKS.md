# 貓咪外觀包與客製交付

本功能屬於包含角色包實作的 macOS 開發／QA 版，尚未隨正式版 1.4.5 發布。Windows 與舊版 App 不會讀取本格式。請以 QA 版選單的來源編號辨認要驗收的版本。

## 這一版可以客製什麼

| 項目 | 本版範圍 |
| --- | --- |
| 毛色 | 九種既有底色／花紋預設，以及 16 個部位的覆蓋設定 |
| 異瞳 | 左右眼分別指定顏色；保留原有叉叉／勾勾眼的造型與錄音操作 |
| 鼻子 | 顏色及固定模板提供的鼻子特徵 |
| 項圈、蝴蝶結 | 固定附著位置與配色，隨原有動作繪製 |
| 角色資料 | 獨立的名稱、ID、版本、外觀與可選縮圖 |
| 分享與交付 | `.nekocat` 匯入／匯出，以及首次使用的客製安裝包 |

動作沿用 `yui-cat-v1` 造型模板：坐姿、行走、理毛、睡眠與抓起／放下等狀態仍由 App 控制。特徵不會改變錄音取消／完成的點擊區域。明確指定自訂 `image` 時，錄音與問候仍優先使用該圖片。

### 留待之後新增的造型模板

折耳、短腿、長毛輪廓、不同胖瘦與尾巴形狀列入後續模板工作。這些會影響部位定位、輪廓或動作素材，不列入 `yui-cat-v1` 外觀包的能力。本版也不接受任意 SVG、動畫、程式或從照片自動建立新骨架。

## 收到一隻客製貓

已安裝相容 App 時，雙擊 `.nekocat`，或從選單列小黑貓的「匯入貓咪包…」選擇檔案。App 驗證完整內容後，將外觀包保存在本機角色目錄，再套用外觀。原本的問候文字、快捷鍵、API Key 與其他偏好會保留。已安裝的角色可以從「我的貓咪」選單再次選用。

角色資料會複製進 App 的資料目錄；成功匯入後，下載資料夾裡的原始檔可自行移動或刪除。無法讀取、版本不相容或格式不合規的包會被拒絕，不會以半套資料取代目前外觀。

### 編輯與分享

從選單選「自訂貓咪…」，可以調整 16 個部位的底色／花紋，以及左右眼、鼻子、項圈和蝴蝶結。按「儲存並套用」保存角色並套用外觀。

要分享時，可在編輯視窗按「匯出貓咪包…」，或從主選單選「匯出目前貓咪…」。輸出的包只帶這隻貓的外觀與角色資訊，收件者使用自己的 App 設定與 API Key。

### 第一次安裝就帶指定貓咪

客製交付 ZIP 內包含同一份 App，以及兩個內容相同但用途不同的角色文件：

| 檔案 | 用途 |
| --- | --- |
| `FirstCat.nekocatsetup` | 安裝工具交給 App 的首次設定入口；已有外觀選擇或自訂設定時保留原本選擇 |
| `我的貓.nekocat` | 使用者之後想明確套用這隻貓時，雙擊匯入的普通角色包 |

照常執行 `安裝.command` 即可。安裝工具會保留既有 App 位置、簽章身分規則、回復備份與登入項目，並把首次角色文件複製到 App 的待匯入目錄，再交給 App 處理。**把 App 和外觀包放在同一資料夾，或只拖曳 App 到應用程式資料夾，不會自行觸發首次設定。**

初始化使用 macOS 的開啟文件事件，因此 App 尚未啟動或已被登入項目啟動時，都能接收到文件。待匯入副本不依賴下載資料夾持續存在；當次未能開啟 App 時，下次啟動可繼續處理。一般 `.nekocat` 代表使用者明確選擇匯入；`.nekocatsetup` 則遵守首次設定的保留規則。

## 外觀包格式 v1

`.nekocat` 是 ZIP 檔案，根目錄只接受以下條目。`.nekocatsetup` 使用完全相同的 ZIP 內容，只在 App 開啟入口有不同的啟用規則。

| 條目 | 必要性 | 限制 |
| --- | --- | --- |
| `manifest.json` | 必要 | UTF-8 JSON，最多 4 KiB |
| `appearance.json` | 必要 | UTF-8 JSON，最多 16 KiB；只放 `CatAppearance` 外觀物件 |
| `preview.png` | 選用 | PNG，最多 512 KiB，寬高各最多 512 像素 |

ZIP 本身最多 1 MiB，只有 2 或 3 個根目錄檔案，支援 Store 與 DEFLATE，無加密。資料不包含外部路徑、下載網址、帳號、Agent 權限或可執行程式。未知檔案、重複條目、子目錄、符號連結及不相容版本會被拒絕。使用 App 匯出可取得符合規格的包；以其他工具製作時，不要額外加入 `__MACOSX`、`.DS_Store` 或包住所有檔案的資料夾。

`manifest.json` 範例：

```json
{
  "schemaVersion": 1,
  "id": "custom-mochi",
  "name": "麻糬",
  "version": "1.0.0",
  "templateId": "yui-cat-v1"
}
```

五個欄位都必填，且不接受其他欄位：

| 欄位 | 規則 |
| --- | --- |
| `schemaVersion` | 整數 `1`，表示包格式版本 |
| `id` | 1–64 個小寫英文字母、數字、連字號或點；首尾需為字母或數字，不接受連續兩點或系統保留檔名 |
| `name` | 1–64 個 Unicode scalar，可用中文；不含首尾空白或控制字元 |
| `version` | 1–32 個英文字母、數字、連字號或點，表示這隻角色自己的版本 |
| `templateId` | 本版固定 `yui-cat-v1`，表示共用的動作／造型契約 |

`id` 是角色身分，和 `appearance.preset` 分開；兩隻以賓士貓為底的角色可以有不同名字與 ID。

`appearance.json` 範例：

```json
{
  "preset": "tuxedo",
  "seed": 1,
  "parts": {
    "tail": { "color": "#8D9295", "pattern": "none" }
  }
}
```

這份設定使用賓士貓底、灰色無花紋尾巴。`appearance.json` 直接放外觀物件，外面**不加** `version` 或 `appearance` 包裝；完整 `cat.config.json` 還包含問候等使用者設定，兩者不能互相直接覆寫。部位與特徵欄位見 [CAT-CONFIG.md](../CAT-CONFIG.md)。

## 本機儲存與更新

App 使用 Foundation 的 Application Support 目錄，角色放在 App 專用資料夾的 `Cats` 下。一般 macOS 安裝對應：

```text
~/Library/Application Support/tw.panh.FreeVoiceType/Cats/
```

App 匯入前先驗證整個包，完整驗證後才更新儲存的角色。外觀包獨立於 `.app`，所以 App 更新可以保留已安裝角色。一般移除工具也會保留這個使用者資料目錄，若需清除可從 Finder 手動刪除。

客製安裝流程會在同一 App 專用資料夾下的 `IncomingCats/` 建立一份 `<UUID>.nekocatsetup`，目錄權限為 `700`、文件為 `600`，供 App 在當次或下次啟動處理；成功處理後由 App 清除該待匯入副本。安裝工具只新增這份限額文件，不替使用者改寫 `cat.config.json`。一般沒有客製角色的安裝包不會建立這個目錄。

外觀編輯與匯出只處理外觀資料。角色包沒有 Groq Key、聊天紀錄、剪貼簿、問候觸發句或系統權限，也不會替使用者安裝第三方執行程式。資料去向見 [PRIVACY.md](../PRIVACY.md)。

## 製作客製安裝包

先在包含角色包功能的 App 中確認外觀可正常載入，再匯出 `.nekocat`。macOS 開發環境可把它和已建置／簽章的通用 App 組成一份交付檔：

```bash
./scripts/package-custom-cat.sh \
  "build/AI語音輸入.app" \
  "build/Mochi.nekocat" \
  "dist/Mochi-macOS.zip"
```

腳本會驗證 App 身分、角色包功能版本與現有簽章，保留原 App 內容，建立新的 ZIP 與 `.sha256`。若輸出檔已存在會停止，請改用新檔名。它不會重新編譯、重簽 App，或產生指向 GitHub 正式 release 的一行安裝腳本。角色包的完整內容由 App 匯入器驗證。

這個交付檔沿用所輸入 App 的發行性質：本機 ad-hoc QA build 仍是 QA build；這個腳本不會把它變成已公證或正式發布的版本。

## 驗收順序

1. 匯入一隻有異瞳、鼻子特徵、項圈和蝴蝶結的貓，確認桌面、錄音浮窗與問候套用相同外觀；叉叉／勾勾眼操作仍正確。
2. 檢查左右行走、理毛、睡眠、抓起與放下；確認花紋、鼻子與配件的附著位置合理，沒有跨姿勢跳色或超出視窗。
3. 匯出後在另一份相容 QA App 匯入，核對角色名稱與特徵一致。
4. 在全新 macOS 測試帳號跑客製安裝流程，確認首次顯示指定角色；另在已選外觀的測試帳號確認選擇與其他偏好保留。
5. 測試不相容模板、損壞 ZIP 和過大素材被拒絕後，既有角色仍能使用。

自動測試與原生渲染截圖只能覆蓋一部分驗收；真機拖曳手感、配件遮擋和不同螢幕比例仍需桌面 QA。尚未完成的驗收不應當作已通過或已發布。
