# PRD：貓咪的手（VPS 工作區與權限）v1

## 0. 一句話

**架構：** 眼睛和耳朵留在你的 Mac 帳號，做事的手放在 VPS 的受限工作區，第二個 Mac 帳號以後再說。

**體驗：** 你只會覺得「交代貓咪 → 貓咪做好」。權限、機器、同步、鑰匙更新都由工程吸收。只有三種時刻會請你出手：**第一次給鑰匙、需要你登入、要做收不回的事**。

v1 要做到：VPS 上的貓可以用自己的 Chrome 操作網頁、在 GitHub 開 PR、透過資料夾跟你交換檔案。你隨時看得到它在做什麼，收不回的事一律由你本人按下去。

## 1. 為什麼要做

### 1.1 Mac 記憶體（2026-10-23 中午實測）

| 指標 | 數值 | 白話 |
|---|---|---|
| 實體記憶體 | 8 GB（M1） | — |
| swap 使用 | **7.07 GB／8 GB** | 已經大量拿硬碟當記憶體，所以會卡 |
| 累計 pageouts | 2,302,168 | 長期一直在把記憶體搬到硬碟 |
| node 程序 | **70 個** | 每個 AI session 各自開一整套 MCP 伺服器：`node_repl` 12、`server.mjs` 10、`searchconsole-mcp` 6、`xcodebuildmcp` 5… |

結論：拖慢 Mac 的不是某個太重的功能，而是**閒置的 AI session 沒關，每個都帶著一整套 MCP 伺服器常駐**。長任務搬到 VPS 是對的；Mac 本身也要清理（第 8 節）。

### 1.2 VPS（2026-10-23 唯讀實測）

- Hostinger，x86_64，**2 vCPU、7.9 GB RAM、沒有 swap**，硬碟可用 87 GB。
- 只有一個一般使用者 `neighbor`（沒有 sudo）。執行中：`neighbor-office.service`（貓咪辦公室）和 Caddy（https://office.nekonode.cloud）。
- 已安裝 TigerVNC 和 XFCE。**還沒有 Chrome／Chromium、`gh`、node。**
- 辦公室目前的 Codex 是**唯讀**：不能執行 shell、不能操作電腦、不能改外部系統。

### 1.3 GitHub 現況（2026-10-23 唯讀實測）

- macOS repo 是**公開** repo。`main` **沒有分支保護**；發布用的 environment `macos-release` **沒有審核規則**。
- CI（`build.yml`）：PR 和一般分支的 build job 不帶秘密，這部分沒問題。但 `free-release-check` job 只要有東西 push 到 **`main` 或 `codex/neko-cicd-updates`**，就會把**簽章憑證和 Sparkle 私鑰**交給 `scripts/release-macos.sh`。Sparkle 私鑰能簽 App 更新，已安裝的使用者都會信任這些更新。
- 意思是：**誰能 push 到這兩個分支，誰就能讓 CI 碰到「能簽 App 更新」的鑰匙。** 這決定了第 5.6 節的設計。
- nekonode-site 是**私人** repo，`main` 一合併就上線；其他分支會觸發 Vercel 預覽部署。

### 1.4 現在缺什麼

辦公室已經會「想」和「寫」，但還沒有「手」。這份 PRD 補上手，先把權限設計好，再把權限藏到使用者感覺不到的地方。

## 3. 使用者體驗：工程做，使用者無感

### 3.1 三條原則

1. **平常無感。** 可以退回的事直接做，做好才告訴你。介面上不出現等級、機器、帳號類型、同步或鑰匙到期這些字。
2. **關鍵時刻有感，而且只要一下。** 只有三種時刻請你出手：第一次給鑰匙、需要你登入、要做收不回的事。每次都說清楚「為什麼、大約多久」，一個按鈕直接到位。
3. **想查查得到。** 每件工作都有預設收起的「詳細」：用了哪把鑰匙、去過哪些網站、改了哪些檔案、push 到哪個分支。給你稽核用，也方便以後的人除錯。

### 3.2 使用者看得到的，全部只有六樣

| 你看得到的 | 在哪裡 | 用途 |
|---|---|---|
| **對話** | 手機和 Mac 的瀏覽器（同一個網址） | 交代工作、看成果；「工作過程」可以展開 |
| **等你點頭** | 對話裡的卡片，加上通知（D11） | 登入、合併、寄出、給新鑰匙；一個按鈕直接開到要按的地方 |
| **看看貓咪** | 對話裡、卡片上 | 看貓咪的桌面；按「我來」接手，按「交還」讓它繼續 |
| **貓咪資料夾** | Mac 的 `~/貓咪/` | 「交給貓咪」放東西給它，「貓咪交回」收成果 |
| **貓咪的鑰匙** | 設定 | 貓咪能開哪些門（例如：GitHub 2 個專案、貓咪的 Google 帳號），最近一次使用時間，每一把都能收回 |
| **先停一下** | 對話頂端（現有按鈕） | 全部暫停；同一處有「收回所有鑰匙」，要再確認一次 |

名稱延續現有介面「交給貓咪」「先停一下」的語氣；要改名直接改這張表。

### 3.3 工程吸收掉的事

| 工程上做的 | 你感覺到的 |
|---|---|
| 兩個 Linux 使用者、worker 專用憑證、loopback 修補 | 什麼都沒有，只有一隻貓 |
| 先讓「腦」判斷，需要動手才自動轉給「手」（第 7 節） | 同一段對話；貓咪說「這要上網操作，我去做了」 |
| L0–L2 自動、L3 停下來、L4 沒有鑰匙（5.3） | 可以退回的事直接做好；收不回的變成一張「等你點頭」；跟錢有關的事，貓咪說「這我不碰」 |
| GitHub App，每件工作發一把一小時、只限一個 repo 的臨時鑰匙；由辦公室代為 push 到 `neko/*` | 「貓咪開了一個 PR」；不用續鑰匙；PR 掛貓咪的名字 |
| 讓 CI 秘密碰不到（5.6） | 什麼都沒有 |
| 單向同步、資料夾一變動就推、每分鐘拉回 | 東西放進資料夾，貓就拿得到；它做好的東西會自己出現 |
| 同步時不覆寫你的檔案 | 「貓咪不會改你的原檔，改好的版本會另外放回來」：這是一個承諾，不是限制 |
| WebSocket 轉接 VNC，密碼自動帶入 | 按「看看貓咪」，畫面就出來 |
| 你接手時暫停它的瀏覽器動作，交還後繼續 | 你一動手，貓就停；交還，它就接著做 |
| 心跳檢查、自動重試 | 斷線不會打擾你，連續三次失敗才告訴你 |
| Gemma 和瀏覽器任務互斥、佇列、swap | 最多看到「排隊中，前面還有 1 件」 |
| 步驟截圖 | 在手機上看得到它剛剛在哪一頁做了什麼 |
| 稽核紀錄 | 收在「詳細」裡，想看才展開 |

### 3.4 不能藏的四件事

| 時刻 | 怎麼讓你知道（盡量輕） | 頻率 |
|---|---|---|
| 第一次給某把鑰匙 | 一句話說清楚能開哪扇門。網站要特別講：「登入後，我在這個網站能做的事跟這個帳號一樣多。」 | 每把一次 |
| 收不回的事 | 一定停下來，等你按 | 每次 |
| 資料會送到外部 AI 公司 | 輸入框下方固定一行小字；附件第一次送出時多提醒一次 | 一直在，但很小 |
| 貓咪正在用某個帳號做事 | 對話裡寫「正在 GitHub 上…」 | 做的當下 |

**為什麼不能藏：** 你第一次看到一個沒預期的 PR，或一封用你名義寄出的信，對整個系統的信任就沒了。藏掉這四件換來的順暢，最後要用信任付代價。

### 3.5 互動預算（每個情境你最多要動幾下）

| 情境 | 你要做的 | 上限 |
|---|---|---|
| 在外面用手機叫它開 PR | 送出 → 收到「PR 開好了」→ 點「去看 PR」→ 在 GitHub 按 Merge | 打字＋3 次點擊 |
| 下載已登入網站的報表 | 送出 → 報表自己出現在「貓咪交回」 | 打字＋0 次 |
| 網站要重新登入 | 點「幫貓咪登入 X」→ 在畫面裡登入 → 點「交還」 | 登入本身＋2 次點擊，**不用再按「繼續」** |
| 第一次用 GitHub | 點「給鑰匙」→ 在 GitHub 頁面勾 repo → 安裝 | 大約 1 分鐘，只做一次 |
| 想看它在做什麼 | 點「看看貓咪」 | 1 次 |
| 想自己動手 | 點「我來」 | 1 次（貓咪自動停手） |
| 緊急停止 | 點「先停一下」 | 1 次 |
| 叫它做跟錢有關的事 | — | 0 次：貓咪直接說不碰，附上步驟 |

### 3.6 用到才設定（不做開場設定精靈）

- 不會一開始就要你設定一堆東西。**第一次需要某個東西時才問**，而且說明這次為什麼需要。例如：「要開 PR，我需要 GitHub 的鑰匙。現在設定？（約 1 分鐘）」
- 選「這次先不用」時，貓咪仍然盡量交出成果：例如把修改做成 patch 放進「貓咪交回」，附上步驟。
- **營運者的一次性設定不算使用者體驗。** 現在你同時是營運者和使用者。VPS 的 root 設定、建立貓咪的 GitHub App、替手登入 Codex，都是營運者做一次就好，由 Claude 提供逐行指令。以後要開放給別人用，這些要改成自動開通，不在 v1。

### 3.7 貓咪怎麼說（例外狀況的文案）

| 狀況 | 貓咪說 | 按鈕 |
|---|---|---|
| 需要登入 | 「X 要你登入一下，我才能繼續（約 1 分鐘）。」 | 幫貓咪登入 |
| 第一次登入某個網站 | 「登入後，我在 X 能做的事跟這個帳號一樣多。建議用給我專用的帳號。」 | 我知道了，去登入 |
| 需要新鑰匙 | 「我還沒有 nekonode-site 的鑰匙，要給我嗎？」 | 給鑰匙／這次先不用 |
| 收不回的事 | 「PR 開好了。要合併嗎？合併後就會上線。」 | 去合併／先不要 |
| 錢、帳號安全 | 「這件我不碰：跟錢和帳號安全有關的事要你自己來。步驟我整理好了。」 | 看步驟 |
| 排隊 | 「排隊中，前面還有 1 件。」 | — |
| 辦公室連不上 | 「辦公室暫時連不上。這則我先留著，連上就送出。」 | — |

## 5. 權限設計

### 5.1 六條原則

1. **權限鎖在鑰匙上，不靠 prompt。** 網頁裡可能藏著騙 AI 的指令（prompt injection），所以「它不會做」不算保護，「它做不到」才算。
2. **會讀網頁的一方，手上不拿長期鑰匙。** GitHub 鑰匙放在辦公室，由固定的程式碼代為 push 和開 PR，手只負責改檔案。
3. **給它自己的帳號，再分享它需要的東西。** 就像請助理：不給你的主帳號，給它自己的帳號，再加一個共用資料夾。
4. **單向信任：只有 Mac 連 VPS。** 就算 VPS 被入侵，損失也只限於 VPS 上那幾把限縮過的鑰匙。
5. **可以退回的自動做，收不回的你來做，錢和帳號安全永遠不碰。**
6. **每個動作都留痕跡**，收在「詳細」裡。

### 5.2 身分隔離（Linux 使用者）

| 使用者 | 擁有什麼 | 不能做什麼 |
|---|---|---|
| `neighbor`（現有） | 辦公室服務、`office.sqlite3`（含生活紀錄）、手機配對、辦公室用的 Codex 登入、**GitHub App 私鑰**、Mac 的 SSH 入口 | — |
| `neko-hands`（新增，沒有 sudo） | worker、自己的 `CODEX_HOME`（你登入一次）、Chrome profile、`workspace/`、VNC 桌面 | 讀不到 neighbor 的家目錄（權限 700）、生活紀錄、配對 cookie、SSH 金鑰、GitHub 私鑰；不能用 sudo |

**任務怎麼交接：** worker 只能呼叫辦公室的 worker 專用 API（第 9 節），拿到「這一件任務＋你明確選的附件」，再寫回結果和步驟。worker 憑證讀不到生活紀錄列表，也不能交辦新任務。

### 5.3 動作分級（只在工程內部用，介面上不出現）

| 等級 | 例子 | 怎麼處理 | 由什麼強制 |
|---|---|---|---|
| **L0 讀** | 公開網頁、「交給貓咪」資料夾、自己的工作區 | 自動 | — |
| **L1 在自己的範圍寫** | 工作區、「貓咪交回」、草稿 | 自動，留紀錄 | 檔案權限 |
| **L2 對外但能退回** | push 到 `neko/*`、開 Draft PR、在共用的 Drive 資料夾新增檔案 | 自動，做好後通知 | 辦公室程式只產生 `neko/*` refspec；App 權限 |
| **L3 收不回或代表你發言** | 合併、刪除雲端資料、寄信或發訊息、發文、接受條款、改帳號設定 | **v1 由你本人做**：卡片一鍵開到要按的頁面 | 鑰匙本身沒有這些權限 |
| **L4 永遠不碰** | 銀行、券商、prop firm、交易所、加密錢包、密碼管理器、Apple ID、你的主 Google 帳號、2FA、改密碼 | 根本不放上 VPS；貓咪會婉拒，並附上步驟 | 鑰匙不存在 |

**網站的限制要講清楚：** 在已經登入的網站裡，貓咪能做這個帳號能做的所有事，網站本身不會幫你分級。所以網站這邊真正的控制只有一個：**登入的是誰的帳號**（5.4、5.5）。

**交易帳號**（券商、prop firm、TradingView 下單）一律算 L4。就算以後要讓 AI 協助交易，也應該走既有的 webhook → 風控引擎路線，不讓瀏覽器 agent 拿到登入狀態。

### 5.4 帳號與鑰匙

| 帳號 | 給法 | 範圍 | 放在哪裡 | 撤銷 |
|---|---|---|---|---|
| **GitHub** | **貓咪的 GitHub App**（營運者建立一次，用 manifest 一鍵建立；不行就退回手動填表） | 安裝在你勾選的 repo；Contents 讀寫、Pull requests 讀寫、Metadata 唯讀；**不給** Workflows、Administration、Secrets | 私鑰只放在 neighbor（權限 600）。每件工作由辦公室發一把**一小時、只限該 repo** 的臨時鑰匙，手拿不到 | 鑰匙清單按「收回」：停止發新鑰匙並撤銷已發的；或到 GitHub 解除安裝 App |
| **VPS Chrome** | 你在「看看貓咪」裡親手登入 | **只登入貓咪自己的帳號**，或本來就沒什麼權限的帳號 | `~neko-hands/chrome-profile/`（權限 700） | 鑰匙清單裡按某個網站的「收回」，清掉那個網站的登入狀態；被入侵時另外到該網站「登出所有裝置」 |
| **Google** | 貓咪專用帳號，第一次需要用到時才建立 | 你把指定的 Drive 資料夾分享給它（編輯者） | 只存在 VPS Chrome | 取消分享，或停用帳號 |
| **Codex（手用）** | neko-hands 自己的 `CODEX_HOME`，你用裝置碼登入 | 你的 ChatGPT 方案額度 | `~neko-hands/.codex/` | `codex logout`，或到 ChatGPT 撤銷裝置 |
| 其他（Notion、各種 SaaS） | v1 不給 | 以後用「用到才設定」一個一個加 | — | — |

**為什麼用 GitHub App，不用 personal access token（v0.1 的推薦）：**
- 不用每 30 天續一次。
- PR 會以「貓咪[bot]」的名義出現，不會混進你自己的提交；你也能正常按 Approve（GitHub 不讓你核准自己開的 PR）。
- 鑰匙能縮到每件工作、一個 repo、一小時。

**更正 v0.1：** v0.1 的 D3 推薦「在貓咪的 Chrome 登入 GitHub 網頁」，撤回。用你的帳號登入 GitHub 網頁，就能刪 repo、改設定、直接合併，等於繞過上面所有限制。

### 5.5 為什麼不複製 Mac Chrome 的 cookie

1. **只能全給，不能挑。** 主 profile 的 cookie 包含所有已登入的網站：Gmail、銀行、Claude、ChatGPT、券商後台。
2. **全部交給一個會讀網頁的 agent。** 它一旦被網頁誘導，損失就是全部。換成 VM 也沒用，因為問題出在授權範圍，不在機器。
3. **技術上也不穩。** Mac Chrome 的 cookie 用鑰匙圈裡的金鑰加密；換到雅加達的 IP 使用，網站也可能要求重新驗證。
4. **主 Google 帳號特別危險：** 它通常是你所有帳號「忘記密碼」的收信箱，拿到它就等於拿到全部。

### 5.6 GitHub 寫入由辦公室代勞

**問題：** 第 1.3 節提到，push 到 `main` 或 `codex/neko-cicd-updates`，CI 就會碰到 Sparkle 私鑰。只要手上有一把「能 push 任意分支」的鑰匙，被誘導的 agent 就可能改 build 腳本，讓 CI 把秘密送出去。

**做法：**
- **讀：** 辦公室用一把一小時的**唯讀**臨時鑰匙，把 repo clone 到手的工作區，鑰匙不留在 git 設定裡。
- **寫：** 手做好 commit 後呼叫 `/api/worker/push`。辦公室確認以下三點，才用一小時的寫入臨時鑰匙 push，並開 **Draft PR**：
  1. 這件工作只碰一個 repo。
  2. 沒有改動 `.github/workflows/`（App 沒有 Workflows 權限，GitHub 本身也會擋）。
  3. refspec 一定是 `HEAD:refs/heads/neko/<任務短碼>`。
- 辦公室**從來不 merge、不刪分支、不打 tag**。

**效果：** 不管 repo 有沒有分支保護、不管你是哪個 GitHub 方案，貓咪都碰不到 `main`、`codex/neko-cicd-updates`、tag，也碰不到帶秘密的 CI。使用者對這些完全無感。

**營運者加固（建議做，跟貓咪無關也該做）：** macOS repo 是公開 repo，免費就能設 `main` 分支保護，以及 `macos-release` environment 的必要審核者，現在兩者都沒有設。

**nekonode-site：** 貓咪推的分支會觸發 Vercel 預覽部署，預覽建置會執行分支上的程式，也拿得到 Preview 環境變數。**確認 Preview 環境變數裡沒有正式金鑰（U1）之前，不放進 App 的安裝範圍。**

### 5.7 貓咪資料夾

| 位置 | 誰能寫 | 方向 |
|---|---|---|
| Mac `~/貓咪/交給貓咪/` → VPS `/srv/neko-handoff/給貓/` | 只有 Mac（經 `neighbor`） | 資料夾一有變動就推過去（launchd `WatchPaths`）；neko-hands **唯讀** |
| VPS `/srv/neko-handoff/貓交回/` → Mac `~/貓咪/貓咪交回/` | 只有 neko-hands | Mac 醒著時每分鐘拉一次；**不刪 Mac 上的檔案**，同名檔先備份再覆蓋 |
| VPS `~neko-hands/workspace/` | neko-hands | 自由區：clone、下載、暫存 |

- `/srv/neko-handoff/` 用群組權限控管：`給貓/` 只有 neighbor 能寫，`貓交回/` 只有 neko-hands 能寫，雙方都能讀。
- 它需要 Obsidian 筆記時，你放**複本**進「交給貓咪」，不開放整個 vault。
- 現有的手機附件上傳照舊，是最常用的那條路；資料夾用在大量檔案。

### 5.8 前置修補：辦公室信任 loopback

**現況（讀過程式碼確認）：** `office.py` 的 `boundary()` 只要看到 Host 是 `127.0.0.1:8421`、又沒有轉送標頭，就判定為 local 模式。`authenticate()` 在 local 模式什麼都不檢查，`/api/bootstrap` 會直接回傳 token（約第 1153、1180、1237 行）。

**現在沒事，是因為** VPS 上只有 `neighbor` 一個使用者。

**加入 neko-hands 之後，** 會讀網頁的 agent 跟辦公室共用同一個 loopback：它只要發一個請求就拿得到 token，可以讀所有任務和生活紀錄，也可以交辦新任務。

**修法（H2 擇一，推薦 A）：**
- **A.** 辦公室的本機入口改成只有 neighbor 打得開的 Unix socket（權限 600），Mac 的 SSH 通道改成轉送到這個 socket。Caddy 的公網入口另外處理。
- **B.** local 模式也要求一個只有 neighbor 讀得到的本機憑證檔。

**這一項沒完成，就不建立 neko-hands。**

### 5.9 網路

- v1 不限制 neko-hands 的出站連線（它需要上網）。
- 本機服務：辦公室修補後只認 worker 憑證；VNC 和 Chrome 的除錯埠只綁 `127.0.0.1`。neighbor 也連得到這些埠，但 neighbor 本來就是權限較高的一方。
- v2 再考慮用 iptables owner match 擋掉 neko-hands 的 SMTP 等出站連線。

### 5.10 停止與收回

| 你按的 | 工程上做的 |
|---|---|
| 先停一下（現有） | 取消正在跑的工作，保留佇列 |
| 收回某一把鑰匙 | GitHub：停止發新鑰匙，撤銷已經發出的；網站：清掉那個網站的登入狀態 |
| 收回所有鑰匙（要再確認一次） | 停止 worker 和 Chrome、撤銷所有 GitHub 臨時鑰匙、關閉 VNC 桌面；只有工程自動做不到的步驟才列給你，例如到 Google「登出所有裝置」 |

v1b 驗收要**實際演練一次**完整撤銷，然後再恢復。

## 6. 看見它在做什麼

**一個畫面，Mac 和手機共用：** 辦公室網頁裡的「看看貓咪」。預設只看；按「我來」接手；按「交還」或關掉，貓咪從原處繼續。

**工程上怎麼做：**
- **畫面元件：** noVNC，跟 PDF.js 一樣隨辦公室一起提供。
- **連線路徑：** 走辦公室現有的 WebSocket（已配對裝置的 cookie＋Origin 檢查），轉接到 VPS 本機的 VNC。VNC 只聽 `127.0.0.1`。
- **密碼：** VNC 密碼由辦公室帶入，你不用輸入。
- **只看模式：** 「只看」是防手滑，不是防你，所以在畫面這一層切換就夠，不需要第二組密碼。
- **接手：** 你接手時，worker 暫停瀏覽器動作，工具呼叫先等著；你交還後再繼續（U7）。
- **步驟截圖：** 每個瀏覽器步驟存一張截圖，放進「工作過程」。

**風險說明：**
- VNC 本身不對外。能看貓咪的條件，跟能交辦工作的條件一樣（已配對的裝置），沒有多開一扇門。
- 代價：配對 cookie 外洩時，對方也看得到貓咪的桌面；不過拿到 cookie 的人本來就能叫貓咪做事。

**退路：** 現有的 Mac「接手控制」（螢幕共享，經 SSH 通道）保留，v1a 先用它；網頁壞掉時也還有這扇備用門。

**手機登入的限制：** 在手機上透過遠端畫面登入是可行的，但密碼管理器無法自動填入遠端畫面，長密碼建議回 Mac 再登入。v2 的「單站鑰匙轉交」可以解決這個問題，代價是：
- 要做一個 Chrome 擴充功能。
- 有些網站換 IP 後會要求重新驗證。

## 7. 執行者與自動轉交

- **使用者不用選「手」。** 預設是「貓咪自己決定」：
  1. 先由現有的唯讀 Codex（腦）判斷。
  2. 它判斷需要上網操作、改程式或存取檔案時，回傳一段結構化的「需要動手」。
  3. 辦公室自動在同一段對話裡建立子任務交給手，沿用現有的 `parent_id` 接續機制。
- **捷徑：** 交辦內容明確提到 PR、GitHub、下載、登入、網站時，直接交給手，省一輪判斷。H5 評估要不要做。
- **模型選單**移到「進階」，保留手動指定。
- **手的執行環境：** neko-hands 自己登入的 Codex CLI，可以用 shell 和網路，工作目錄限定在 `workspace/<任務 UUID>/`，作業系統的使用者本身就是沙箱邊界。瀏覽器工具用 Chrome DevTools MCP 或 Playwright MCP，連到 VNC 桌面上已經開著的 Chrome（U3）。
- **限制：**
  - 一次只跑一件「手」的任務；Gemma 和「手」互斥。
  - 每件任務最長 30 分鐘、事件最多 4 MB，超過就停下來並保留部分成果。
- 原本的 `codex`（唯讀）和 `gemma` 執行者不變。

## 8. 記憶體與資源

### 8.1 Mac（今天就能做，不用等 v1）

1. **封存閒置的 Claude Code 和 Codex session。** 每個 session 都帶著自己那一套 MCP 伺服器，要關掉 session，它的 node 程序才會結束。
2. 停用沒在用的 MCP：例如不做 iOS 時關掉 `xcodebuildmcp`。
3. Mac 上不跑 Docker Desktop（它會預留一整塊 Linux VM 的記憶體）、本機大模型或第二個 macOS 帳號。
4. 長任務一律交給 VPS。Mac 闔上蓋子，VPS 照樣做。

### 8.2 VPS（8 GB、沒有 swap）

| 項目 | 估計 | 備註 |
|---|---|---|
| 系統＋辦公室＋Caddy | 約 1.8 GB | 實測目前用掉 1,795 MB |
| XFCE＋TigerVNC | 0.3–0.5 GB | 估計，H1 實測 |
| Chrome（少量分頁） | 1–2 GB | 估計，H3 實測 |
| Codex CLI | 0.2–0.4 GB | 估計 |
| Gemma 3 4B（開啟時） | 約 3–4 GB | 不跟瀏覽器任務同時跑 |

建議加 **4 GB swapfile**（D8）。沒有 swap 時，記憶體一用完，Linux 會直接砍掉程序，可能砍到辦公室。

## 9. 介面契約（概要，H2 定稿）

| 端點 | 用途 | 憑證 |

## 11. 什麼時候才需要第二個 Mac 帳號

以下**三項同時成立**才做：

1. 要操作的軟體**只有 Mac 版**，而且沒有 API 或網頁版可用。
2. 這件事必須在你使用 Mac 的同時進行，不能等你離開再做。
3. Mac 的記憶體負擔得起。現在是 8 GB、swap 已經用滿，**這一項目前不成立**。

到時候沿用本 PRD 的權限設計：標準使用者、只開放交接資料夾、只登入貓咪自己的帳號。
